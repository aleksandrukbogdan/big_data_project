# Сбор IT-тендеров с rostender.info

Забираем открытые тендеры IT-категории и кладём сырые данные в три хранилища. Расписанием занимается Apache Airflow 2.10 в Docker.

## Хранилища

| Куда | Что лежит | Почему так |
|---|---|---|
| MinIO | исходные XML и HTML | файл сохраняется как скачали, по дате и номеру прогона |
| MongoDB, коллекция `ods.tenders` | карточка тендера | поля не всегда одинаковые, дату с HTML часто не достать |
| PostgreSQL, порт 5433 | таблицы `ods.tender_locations` и `ods.tender_prices` | город, регион и цена удобно выбирать запросом |

У Airflow свой PostgreSQL, только для служебных данных. К тендерам он не относится.

## Процессы

```
rostender.info
    ├─ ods_raw_to_minio             → MinIO
    ├─ ods_tenders_to_mongo         → MongoDB
    └─ ods_geo_prices_to_postgres   → PostgreSQL
```

В каждом процессе три шага: скачать, разобрать, записать.

`ods_raw_to_minio` сохраняет `rss.xml` и `category.html` в бакет `ods-tenders` по пути `raw/dt=дата/run_id=.../`.

`ods_tenders_to_mongo` собирает из ленты и страницы карточки и обновляет документ по id тендера.

`ods_geo_prices_to_postgres` достаёт из текста «Цена» и «Место поставки», регион берёт из адреса `/region/.../`, и обновляет строки по тому же id.

Повторный запуск не создаёт дубли.

## Как поднять

```bash
docker compose up --build airflow-init
docker compose up -d
```

- Airflow: http://localhost:8080, логин `airflow`, пароль `airflow`. Если список пустой, обнови страницу. Прямые ссылки: `/dags/ods_raw_to_minio/grid`, `/dags/ods_tenders_to_mongo/grid`, `/dags/ods_geo_prices_to_postgres/grid`
- Файлы MinIO: http://localhost:9002. В этой версии MinIO нет своей консоли на порту 9001, порт 9000 — это API, не страница.
- Карточки MongoDB: http://localhost:8081, логин `admin`, пароль `admin`, база `ods`, коллекция `tenders`
- Таблицы PostgreSQL: http://localhost:8082. Система PostgreSQL, сервер `postgres-ods`, пользователь `ods`, пароль `ods`, база `ods`. Адрес http://localhost:5433 в браузере не откроется: это порт базы, не сайт.

Процессы сначала стоят на паузе. Её нужно снять и нажать Trigger.

## Сравнение

Один и тот же набор тендеров записали во все три хранилища и замерили время записи, время поиска по id и объём. Скрипт: `scripts/benchmark_stores.py`. Цифры и картинки: `benchmark_results.md`, папка `figures/`.

Прогон 2 октября 2026, 20:43. Взяты файлы последнего ручного запуска Airflow: 37 карточек, сырые XML и HTML.

| Хранилище | Запись, мс | Поиск по id, мс | Объём |
|---|---:|---:|---:|
| MinIO | 248 | 1.8 | 1.3 МБ, 2 файла |
| MongoDB | 30 | 1.4 | 35 КиБ, в коллекции 56 документов |
| PostgreSQL | 12 | 0.8 | 224 КиБ, в таблицах 76 строк |

В MongoDB и PostgreSQL строк больше, чем 37: там остались и предыдущие запуски. Поиск везде быстрее 2 мс. Запись в MinIO дольше, потому что туда уходит вся страница целиком, около 1.3 МБ. В базы попадает уже разобранный текст, он намного меньше.

| | MinIO | MongoDB | PostgreSQL |
|---|---|---|---|
| Исходный файл целиком | да | нет | нет |
| Жёсткая схема | нет | нет | да |
| Выборка по цене и региону | неудобно | можно, но тяжелее | обычный SQL |

Сырые файлы лучше держать в MinIO: их не нужно заранее разбирать. Город и цену удобнее читать из PostgreSQL. MongoDB имеет смысл, если поля карточки часто меняются. На этих тендерах поля стабильные, поэтому для работы хватает MinIO плюс PostgreSQL. MongoDB оставлен в стенде, чтобы сравнить три разных способа хранения.
